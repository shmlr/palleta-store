# Palleta Purchase Flow Audit
**Срез:** 20.10.2026. **Режим:** READ ONLY, без оформления заказа и изменения сайта.

## Задача
Проверить цепочку «главная → меню → порции → список покупок → предварительная заявка WhatsApp → ручное подтверждение магазина». Проверять конверсию от желания купить до фактического завершения покупки, а не только вёрстку.

Контрольный issue: https://github.com/shmlr/palleta-store/issues/13

## Подтверждено анализом текущего кода

| Приоритет | Контроль | Предварительный вывод |
|---|---|---|
| P0 | «Куплено» и предварительная WhatsApp-заявка | В `app.js` чекбокс `data-check` обновляет только набор `checkedItems` и счётчик, но `whatsappOrderText` перебирает все `basket.items`. Риск повторной покупки. Браузерный тест воспроизводит. |
| P0 | Публичные сведения 1С | `menu/products.json` включает внутренние `source_notes`, в том числе исторические детали складских сверок. Публичную схему надо разделить с внутренними данными и проверить историю Git. |
| P1 | Текущий остаток и сумма | Все 30 товаров имеют неопределённое наличие. Нельзя обещать собранную или подтверждённую корзину без проверки магазина. |
| P1 | Текст для закупщика | В покупательском `app.js` виден блок «Какие SKU стоит проверить», предназначенный для внутренней работы. |
| P1 | Геосценарий | На главной нет подтверждённого маршрута к торговой точке; адрес требуется утвердить у владельца. |
| P2 | Бюджет | Выбор бюджета не участвует в ранжировании рецептов; ограничение описано лишь как ориентир. |
| P2 | Рецепты | 44 редакционных рецепта; требуется проверка поваром/технологом, особенно безопасности и аллергенов. |
| P2 | Маркетинг | Нет подтверждённых метрик конверсии до фактической покупки. |

## Автоматический прогон
Команда выполняется только в изолированном GitHub Actions на коде ветки:
```sh
python3 -m http.server 8877 --bind 127.0.0.1 &
node tools/audit_purchase_flow.cjs
```
Тест запускает реальный Chromium на 360 и 390 px, проверяет 3/7 дней, выбор 4 человек, сохранение после перезагрузки, «Куплено» и «Уже есть дома», пикник, состав WhatsApp-сообщения, клубные цены, отсутствие подтверждённого итога и перелив по ширине. **WhatsApp не открывает и не отправляет**. Отчёт `report.md`, `findings.json` и скриншоты сохраняются как артефакт `purchase-flow-audit`.

## Критерии будущего выпуска
1. **P0-01:** позиции с отметкой «Куплено» не должны повторно включаться в заказ, если предназначение действия именно «уже приобретено». UX-решение подтвердить с владельцем: желательно отдельные понятные состояния «Купить» / «Уже есть дома» / «Куплено», согласованные с заявкой.
2. **P0-02:** публичная выгрузка только allowlist полей. Нет `source_notes`, количественных остатков, служебных кодов, закупочной информации и исторических внутренних сведений. Провести отдельную проверку уже опубликованной истории GitHub.
3. **P1-01:** опубликовать точный адрес соответствующей торговой точки и работающий маршрут, после подтверждения.
4. **P1-02:** убрать сведения для закупщика из покупательского интерфейса, оставить только понятные статусы товара.
5. **P1-03:** зафиксировать, кто принимает заявку, в какие часы и как магазин подтверждает замену/сумму/доставку.
6. **P2-01:** тест конверсии 14 дней: визит, открытое меню, созданный список, WhatsApp-переход, вручную подтверждённая покупка, повторный визит. Никаких предположений о конверсии без фактов.

## Живые проверки
Автотест не подтверждает реальные продажи, получение сообщений, корректность клубной цены на кассе, доставку, наличие или качество рецептов. Необходимы проверка управляющим магазина и закупщиком, тестовый контакт оператора, 5–7 покупателей, повар/технолог и юридическая сверка публичной оферты/информации о продавце.

## Политика
Это аудит, а не автоматическое исправление. Не вносить изменения в `main`, публичные цены, 1С, DNS или внешние мессенджеры по результатам прогона без утверждённого отдельного PR.
