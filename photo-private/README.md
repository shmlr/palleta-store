# Паллета Фото v0.3 · защищённый пилот

**Статус: DRAFT, НЕ РАЗВЁРНУТО.** Код лежит в feature-ветке; v0.2 на https://palleta.store/photo/ не изменена.

## Архитектура

- Cloudflare Worker одновременно отдаёт приложение и защищённое API на *одном HTTPS-адресе*.
- Cloudflare Access допускает только одобренных сотрудников. Worker **дополнительно проверяет** RS256-подпись Access JWT, издателя и AUD.
- Письма проверяющих перечислены в секрете REVIEWER_EMAILS. Остальные авторизованные сотрудники видят **только свои** фотографии.
- Cloudflare R2 (приватный bucket) хранит файлы и JSON решения. База данных для 50–500 пилотных фото пока не нужна.
- Фото после утверждения **не публикуется автоматически** на palleta.store и не загружается в 1С.
- Мобильная обработка вписывает фотографию в белый квадрат 1200×1200. Удаление фона отсутствует. Файл не проходит проверку соответствия товару автоматически.

## Настройка после проверки кода

1. В Cloudflare создайте *приватный* R2 bucket с именем \`palleta-photo-private\`. Не включайте public access, r2.dev или custom-domain public bucket.
2. Создайте Cloudflare Zero Trust Access с учётными записями только нужных сотрудников. В Access App защитите **весь Worker**, включая workers.dev и preview-адреса, либо выключите недоверенные пути доступа. Правила Access определяют, кому разрешено войти, независимо от роли.
3. Получите Team Domain и Application AUD у приложения Access. Не кладите их в GitHub.
4. В папке \`photo-private/\` выполните \`npm install\`, затем:
   - \`npx wrangler secret put TEAM_DOMAIN\`
   - \`npx wrangler secret put POLICY_AUD\`
   - \`npx wrangler secret put REVIEWER_EMAILS\` (через запятую, например электронные адреса проверяющих, не реальные персональные данные в репо).
5. Выполните \`npm test\`, \`npm run check\`, затем \`npm run deploy\`.
6. Проверьте с двумя учётными записями: сотрудник видит только своё, проверяющий видит всех; посторонний получает отказ, а не доступ к статике и изображениям.
7. После успешной проверки можно привязать отдельный адрес \`photo.palleta.store\`. **Не менять** рабочие DNS сайта без отдельной проверки.

## Работа сотрудников

Сотрудник находит код товара, снимает фото с телефона, проверяет кадр и нажимает «Отправить на проверку».
Проверяющий открывает вкладку «Очередь», нажимает «Утвердить» или «Переснять» с причиной. Сотрудник видит результат у себя.

## Обязательные ограничения

- Не размещать реальные каталоги 1С в публичном GitHub.
- Не использовать фотографии и названия из текущей v0.2 как персональные данные сотрудников или надёжную идентификацию товаров.
- Не использовать данную версию как источник истины для НСИ; код вводится вручную, модуль пока не сверяет его с базой.
- Для пилота хранить не более 500–1000 фото. При росте заменить сканирование R2 по JSON-файлам индексируемой БД и добавить реестр аудита.
- Установка на телефоне зависит от браузера. В режиме без интернета синхронизация не гарантируется; заявлять offline-работу нельзя.
- В случае отсутствия Team Domain, AUD или токена Access приложение закрыто (401/503).
- Внести одобренные фото на сайт можно будет только отдельным процессом согласованной публикации.

## Приёмочные тесты перед активацией

- Отказ без JWT; отказ при неправильном issuer/audience и истёкшем JWT.
- Отказ при попытке читать чужой снимок сотрудником и менять статус без роли проверяющего.
- Загрузка JPEG, PNG, WebP с проверкой фактического формата и лимита 6 МБ.
- Проверка отправки с другого Origin, ошибок сохранения R2 и повторного решения.
- Повторный вход с телефона показывает сохранённый на сервере снимок; второй сотрудник не видит его; проверяющий видит.
- После «Утвердить» публичный сайт не меняется.
